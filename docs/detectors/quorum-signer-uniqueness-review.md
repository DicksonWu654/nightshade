# quorum-signer-uniqueness-review

Availability: opt-in. Severity: info. Confidence: high in the static source relationship.

The rule reviews directly presented entry-parameter vectors of 3..16 signer claims under the Compact 0.34.0 ZKIR3 profile. Each represented claim must contain one canonical ECDSA signature, one canonical Secp256k1 point and one Bytes<32> commitment. It requires the canonical ECDSA verifier outcome for every claim, a keccak256 message of that claim's commitment, a required equality binding the commitment to the persistent hash of its public key's exact native X/Y coordinates, and required membership of every commitment in the same preexisting Set revision. A required comparison checks the fixed presented count against a supplied Uint threshold.

Within that complete successful history, adjacent scalar commitment inequalities are enforced and one or more non-adjacent inequalities are absent from the required scalar equality/inequality closure. Adjacent inequality alone does not establish pairwise uniqueness. The observation identifies the missing pairs; it does not establish that duplicates can satisfy other protocol checks, that the threshold is the sole authorization gate, or that a transaction or bypass is feasible. Independently established uniqueness can make a match intentional. Review whether the threshold counts distinct signers, and enforce the protocol's complete uniqueness condition if needed.

Matching uses canonical call identities, represented entry operands, exact native digest inputs, registry revisions and required predicate snapshots. Application namesakes, ordinary sequences, two-claim vectors, unrequired verifier outcomes and complete pairwise inequality checks do not match. Aliases preserving supplied snapshots remain exact; shared wildcard storage regions and dependency unions cannot establish equality. A condition can be required in one successful branch history without being universal across the entry; findings make only that history's relationship claim.
